Features

Everything DuckView does.

One native DuckDB engine per workspace, wrapped in the tooling analysts, teams and agents actually need.

Query & ingest

  • Parquet, CSV/TSV, JSON/NDJSON, Excel, Arrow/Feather, DuckDB files, Delta and Iceberg table directories
  • S3, Cloudflare R2, Google Cloud Storage and Azure objects via encrypted cloud connections
  • Drag-and-drop uploads that land in the jail and become queryable instantly
  • Persistent workspaces: each one a DuckDB file that survives restarts; in-memory scratch workspaces can be made persistent later without losing tables
  • VS Code-style workspace folders: mount any local folder into the explorer
  • Persistent .duckdb workspaces, in-memory scratchpads or MotherDuck (md:)
  • Relative paths in SQL resolve against the workspace data directory

Overview & profiling

  • Auto-profile on selection: row/column counts, type mix, null ratios, duplicate rows
  • Per-column min / max / avg / median and equi-width histograms, category and timeline distributions
  • SUMMARIZE profiles of any table, file, remote object or SELECT
  • Schema inspection with DESCRIBE … LIMIT 0 — no data scan; Parquet row counts from the footer
  • Selection remembered per workspace; profiles cached and confirmed with a 304

Workbench

  • CodeMirror SQL editor with schema hints, tabs with per-tab Stop, cursor and draft persistence
  • Streaming results over WebSocket with row caps and cell truncation
  • Chart, plan (EXPLAIN / EXPLAIN ANALYZE) and profile views per tab
  • Engine picker: DuckDB or a Databricks SQL warehouse per tab, with one-click materialise into DuckDB
  • Saved-query library with folders and tags; .sql import and export
  • Exports to Parquet, CSV, JSON and streaming Arrow IPC
  • Resizable IDE panes; any component can be hidden and restored

Dashboards

  • KPI, chart (bar, line, area, scatter, pie), table and Markdown widgets
  • Drag-and-drop 12-column grid with per-widget auto-refresh
  • Widgets bound to saved queries or custom read-only SQL
  • Built by agents through create_dashboard_widget
  • Shared with every member of the workspace

Interactive exploration & Mosaic dashboards New

  • Explore: every column of a file, table or query becomes a linked chart — brush one, the rest cross-filter
  • Powered by Mosaic with the workspace engine as its connector: pre-aggregated data cubes keep millions of rows interactive, nothing runs in the browser
  • Mosaic dashboards: declarative YAML/JSON specs with an editor and live preview, generated from any dataset in one click
  • Agents build them through create_mosaic_dashboard; DuckCopilot drafts one on request and validates it against your data before you create it
  • Any table, file, query or inline rows as a dataset; inputs, selections, legends and layouts as in the Mosaic docs
  • Same roles, sandbox, audit and cache as every other query; pre-aggregates invalidated by the data epoch

Lakehouse connectors

  • AWS Glue / SageMaker Lakehouse via Glue's Iceberg REST endpoint (SigV4); federated and S3 Tables catalogs
  • Amazon S3 Tables by table-bucket ARN
  • Any Iceberg REST catalog — Polaris, Lakekeeper, Nessie, Snowflake Open Catalog, Tabular, Unity Catalog IRC — with bearer, OAuth2 or no auth
  • Databricks: browse Unity Catalog, run SQL on a warehouse (Statement Execution API), materialise results, attach UniForm tables natively
  • Lazy browsing; hot-applied secrets and ATTACH statements without restarting engines

AI agents & MCP

  • MCP server over stdio, legacy SSE and Streamable HTTP; 10 tools, 3 resources, 2 guided prompts
  • REST façade POST /api/agent/v1/tools/<tool> and generated OpenAPI 3.0
  • Human-in-the-loop: mutations return an approval challenge until re-issued with dry_run=false
  • Registered agents with workspace-scoped tokens, per-framework snippets, self-test and live inspector
  • Strands, LangGraph, LangChain, CrewAI, AgentCore Runtime / Gateway, Bedrock Agents, custom HTTP

DuckCopilot

  • Context hydrated with tables, columns, files, buckets, the active tab's SQL and SUMMARIZE stats
  • Claude, ChatGPT / OpenAI, Gemini, DeepSeek, OpenRouter, Kimi, Groq, Mistral, Grok, Ollama, any OpenAI-compatible endpoint, Amazon Bedrock, Bedrock Agent and AgentCore
  • Settings console: pick a vendor, paste a key, test, save for everyone — encrypted at rest, live immediately; or bring your own key (kept in the browser)
  • Usage: sessions running now, tokens per day, per model and per person
  • Insert into tab, open in a new tab, run & inspect, fix my query, suggest questions, build dashboard
  • Conversations persisted with the context snapshot of each turn

Sharing & teams New in 1.1

  • Share a workspace with users or teams as Owner, Editor or Viewer; the highest grant wins
  • Personal tabs inside shared workspaces; shared saved queries and dashboards
  • Teams managed by admins and team managers; mirrored from OIDC group claims on every login
  • admin_groups promote IdP groups to platform admin
  • Transfer ownership, leave a workspace, member directory and audit of every grant
  • Agents inherit the member's role — a viewer's token never mutates

Result cache New in 1.1

  • Server LRU (256 MB default) in front of profiles, schemas, plans, widget data and read-only SQL
  • Keys embed file size + mtime and a per-workspace data epoch — exact invalidation, no timers
  • Browser IndexedDB copy with stale-while-revalidate and ETag / 304
  • Last result of every tab restored after a reload; overview selection remembered
  • Live epoch events to every workspace member; per-workspace and global clear

Security

  • Two sandbox layers: a Node filesystem jail and DuckDB's allowed_directories / enable_external_access / lock_configuration
  • One choke point for every query: authorization → SQL guard → HITL → audit
  • AES-256-GCM credential vault with the row id as AAD; scrypt passwords; SHA-256 API tokens shown once
  • Roles ADMIN / USER / READ_ONLY, scoped tokens read / write / mcp / admin with workspace pinning and expiry
  • Local login, OIDC (Authorization Code + PKCE) with group → role mapping
  • Per-workspace memory, thread and timeout limits; extension allow-list; rate limiting

Observability & operations

  • Prometheus metrics: queries, latency, rows, engines, MCP tool calls, HITL challenges, cache hit rate
  • OpenTelemetry traces for every query and tool call, exported over OTLP/HTTP
  • Structured pino logs with request ids; real-time audit feed over WebSocket
  • Liveness / readiness probes; live hardware gauges in Settings
  • SQLite metadata by default, PostgreSQL via DATABASE_URL; migrations run at start

Themes & layout

  • Six themes — Midnight, Graphite, Fjord (dark); Daylight, Professional, Paper (light)
  • Runtime CSS variables so charts, editor and gauges follow; palettes validated for colour-vision separation
  • Override sans / mono fonts and UI scale independently of the theme
  • Resizable splitters everywhere; hide and restore any component per page
MCP tools

Ten tools, one registry.

The same definitions back the MCP server, the REST façade and the OpenAPI document — they cannot drift.

ToolWhat it does
execute_queryGuarded DuckDB SQL with paging — including attached lakehouse catalogs; mutations need dry_run=false after approval
profile_datasetSUMMARIZE statistics of a table, file, lakehouse table or SELECT
inspect_schemaColumns, types and nullability without scanning — files, tables, remote objects, .duckdb files
explain_queryPhysical plan as JSON tree + ASCII, optionally with measured timings
list_accessible_dataWorkspaces, tables and views with columns, every data file, attached lakehouse catalogs
browse_storageOne level of the data directory, cloud buckets and objects, or lakehouse schemas and tables
lakehouse_querySQL on a Databricks SQL warehouse, HITL-gated for non-read statements
save_datasetCOPY … TO Parquet / CSV / JSON inside the jail
list_dashboardsDashboards with their widgets and layouts
create_dashboard_widgetBuild dashboards autonomously; SQL validated read-only and dry-run first
create_mosaic_dashboardInteractive Mosaic dashboards from a declarative spec, validated and bound in the workspace before saving

Resources: duckdb://workspaces, duckdb://schemas/{workspace_id}, duckdb://system/resources, duckdb://guides/mosaic-spec. Prompts: data_quality_audit, sql_optimization, build_mosaic_dashboard.
