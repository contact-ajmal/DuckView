Download & deploy

Pick a way to run it.

Every option gives you the same server: HTTP API, WebSocket streaming, MCP transports and the web UI on port 4200. Node 20+ and the bundled native DuckDB are the only runtime.

Docker Hub — {{image}} ↗ Releases on GitHub ↗ Source (.zip) ↗

1 · Docker Hub image

Multi-arch (linux/amd64, linux/arm64), built by CI on every release with SBOM and provenance, smoke-tested before it is tagged.

docker pull {{image}}:latest        # newest release
docker pull {{image}}:{{version}}         # pinned
docker pull {{ghcr}}:latest    # GHCR mirror
Tagslatest, 1, 1.1, {{version}} (older: 1.0, 1.0.0) Basenode:20-bookworm-slim, runs as duckuser, tini init, healthcheck on /readyz Volumes/data (datasets — the filesystem jail) · /app/meta (SQLite metadata) Extensionshttpfs, azure, arrow, iceberg, delta, excel pre-installed — no network needed at runtime

2 · docker run

The fastest first look. Set JWT_SECRET and ENCRYPTION_KEY for anything beyond that, or sessions and stored credentials will not survive a restart.

docker run -d --name duckview -p 4200:4200 \
  -v duckview-data:/data -v duckview-meta:/app/meta \
  -e JWT_SECRET=$(openssl rand -hex 32) \
  -e ENCRYPTION_KEY=$(openssl rand -hex 32) \
  -e DUCKVIEW_ADMIN_EMAIL=admin@example.com \
  -e DUCKVIEW_ADMIN_PASSWORD='change-me-now' \
  {{image}}:latest

open http://localhost:4200

Mount a host folder instead of the named volume (-v $PWD/data:/data) to query files you already have.

3 · Docker Compose

The repository ships a docker-compose.yml with optional profiles: PostgreSQL metadata, a local Ollama for DuckCopilot, and Prometheus.

git clone {{repo}}.git && cd DuckView
cp .env.example .env            # secrets, admin credentials
docker compose up -d                              # SQLite metadata
docker compose --profile postgres up -d           # + PostgreSQL (set DATABASE_URL in .env)
docker compose --profile ollama up -d             # + Ollama for DuckCopilot
docker compose --profile observability up -d      # + Prometheus on :9090
Data./data is mounted at /data; spill goes to a tmpfs MemoryDUCKVIEW_MEMORY (container limit, default 8g) and DUCKDB_MEMORY_LIMIT (engine ceiling, default 70%)

4 · Kubernetes

Kustomize manifests in k8s/: Deployment with liveness/readiness/startup probes, non-root read-only rootfs, an emptyDir spill volume, a PVC for /data, ClientIP session affinity (keeps SSE streams pinned) and Prometheus scrape annotations.

cp k8s/secret.example.yaml k8s/secret.yaml   # or ExternalSecrets / SealedSecrets
kubectl apply -k k8s/
kubectl -n duckview get pods

DuckDB engines are process-local: scale vertically first. For more than one replica use PostgreSQL metadata, a RWX data volume and session affinity.

5 · From source

A pnpm monorepo: Fastify server + React web app. DuckDB ships as a native module — nothing else to install.

git clone {{repo}}.git && cd DuckView
pnpm install && pnpm build
DUCKVIEW_ADMIN_EMAIL=admin@example.com \
DUCKVIEW_ADMIN_PASSWORD='change-me' pnpm start
# → http://localhost:4200   ·   pnpm dev for hot reload (web on :5173)
RequiresNode 20+, pnpm 10 CLIduckview serve | mcp | migrate | create-user | create-token | config

6 · MCP for your editor

Point Claude Desktop, Claude Code or Cursor at a running DuckView with a token that has the mcp scope (mint one in the Agent & MCP hub or with duckview create-token).

claude mcp add --transport http duckview http://localhost:4200/mcp \
  --header "Authorization: Bearer dv_…"

# stdio alternative
duckview mcp --token dv_… [--workspace <id>]
Configuration essentials

Ten settings cover most deployments.

Everything lives in duckview.config.yaml with ${VAR:-default} placeholders; any key can be overridden with DUCKVIEW__SECTION__KEY. The configuration reference has the full list.

VariablePurposeDefault
JWT_SECRETSigns sessions (≥ 16 chars). Required in production.ephemeral (dev)
ENCRYPTION_KEY32-byte hex for the AES-256-GCM credential vault. Required in production.ephemeral (dev)
DUCKVIEW_ADMIN_EMAIL / _PASSWORDBootstrap admin, created only when no users exist.—
DUCKVIEW_DATA_DIRThe filesystem jail for every DuckDB file read and write../data (/data in the image)
DUCKVIEW_FILESYSTEM_MODEfull for a personal workstation (mount any folder), sandboxed for multi-tenant deployments.full
DATABASE_URLMetadata store: sqlite://… or postgres://…. Migrations run at start.SQLite
DUCKVIEW_ENABLE_EXTERNAL_ACCESSRequired for s3://, gcs://, https:// and MotherDuck sources in sandboxed mode.false
DUCKDB_MEMORY_LIMIT / DUCKDB_THREADSEngine ceiling as a percentage of host RAM or absolute; threads per engine.80% / auto
AUTH_STRATEGY + OIDC_*Switch to SSO (Authorization Code + PKCE); OIDC_GROUPS_CLAIM maps IdP groups to teams.local
COPILOT_PROVIDER + keysanthropic, openai, ollama, bedrock, bedrock_agent, agentcore.none
⚠Upgrading. Metadata migrations are additive and run automatically on start (SQLite and PostgreSQL). Back up /app/meta or your Postgres database before a major upgrade; the DuckDB engines and the data directory are untouched.
